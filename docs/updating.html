Updating Command Maker

How to safely update Command Maker to a new version without losing your aliases, syntax patterns, or configuration.

Before You Update

  1. Back up your config: Copy the entire config/CommandMaker/ folder to a safe location.
  2. Check the changelog: Review what changed between your current version and the new one.
  3. Note your MC version: Make sure the new mod JAR matches your Minecraft version and Java version.

Always Back Up First

While Command Maker tries to preserve your config between updates, a backup ensures you never lose your work. Copy config/CommandMaker/ to a safe location before any update.

Standard Update (Same MC Version)

For minor/patch updates within the same Minecraft version (e.g., 3.1.0 to 3.2.0 on MC 1.21):

  1. Stop your Minecraft server or close the game.
  2. Remove the old Command Maker JAR from your mods/ folder.
  3. Download the new JAR and place it in mods/.
  4. Start the server/game. Command Maker will automatically detect existing config and preserve it.
  5. Run /cmd reload to refresh aliases and syntax in memory.

Major Version Updates (Different MC Version)

When upgrading to a new Minecraft version (e.g., MC 1.20 to 1.21):

  1. Back up config/CommandMaker/.
  2. Update your mod loader (Fabric/Forge/NeoForge) to match the new MC version.
  3. Download the Command Maker JAR for the new MC version.
  4. Copy your backed-up config/CommandMaker/ folder into the new server's config directory.
  5. Start the server and run /cmd reload.

Config Compatibility

aliases.json, syntax.json, and permissions.json are forward-compatible across MC versions. You can copy them directly. Function files (.mcfunction) in config/CommandMaker/Functions/ are also fully portable.

Updating from Deprecated Versions

From MC 1.17 or 1.18–1.20.4 to MC 1.21+

These older versions are deprecated. To migrate:

  1. Back up your config/CommandMaker/ folder from the old server.
  2. Set up a new server on MC 1.21+ with your preferred mod loader (Fabric/Forge/NeoForge).
  3. Copy your backed-up config folder into the new server.
  4. Install the MC 1.21 version of Command Maker.
  5. Your aliases, syntax, and permissions will carry over. The new version adds the Function Manager GUI, update checker, and download system.

From Legacy Fabric (MC 1.8–1.13.2) to Modern Fabric

Config files are compatible. Copy config/CommandMaker/ to the new server. Note that the legacy version lacks the GUI system, function downloads, and some advanced features — these become available after upgrading.

Using the wrong Java version will cause startup errors. The Gradle build system auto-downloads the correct JDK when compiling, but at runtime you must have the right Java installed.

Troubleshooting Update Issues

Mod doesn't load after update

  • Check that Fabric API is the correct version for your new MC version.
  • Verify your Java version matches the table above.
  • Check the server log for specific error messages.
  • Try removing the config temporarily — if the mod loads, there's a config issue.

Aliases missing after update

  • Run /cmd reload to refresh from config files.
  • Check that config/CommandMaker/aliases.json exists and is valid JSON.
  • If you renamed the server directory, make sure the config folder was copied.

JSON parse errors after update

  • Validate your JSON files with a tool like JSONLint.
  • Check for trailing commas — they're the most common JSON syntax error.
  • Restore from your backup if the files are corrupted.

Rolling Back

If an update causes problems, you can always roll back: remove the new JAR, restore your config backup, and reinstall the previous version. Command Maker config files are backward-compatible.
