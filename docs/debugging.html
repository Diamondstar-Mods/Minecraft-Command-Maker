Debugging Aliases

So you created an alias and it doesn't work. Don't worry. This guide walks you through a systematic process to find and fix the problem, from simple JSON validation to advanced debugging techniques.

The Golden Rule of Debugging

Never change more than one thing at a time. Change one thing, test, then move on. Changing multiple things simultaneously makes it impossible to know which change fixed (or broke) the problem.

Step 1: Check Config Syntax with JSON Validators

Most alias problems start with invalid JSON in aliases.json or permissions.json. Minecraft gives a generic "Syntax error" message, but the real problem is often a missing comma, extra comma, or unquoted string.

Common JSON Errors

Error Example Fix
Trailing comma "a": "1", "b": "2", Remove comma after last entry
Missing comma "a": "1" "b": "2" Add comma between entries
Single quotes 'key': 'value' Use double quotes: "key": "value"
Unquoted keys {key: "value"} Quote keys: {"key": "value"}
Extra closing brace {"a": "1"}} Match braces properly
Missing closing brace {"a": "1" Add closing brace

Invalid JSON Disables All Aliases

If your aliases.json file contains invalid JSON, Command Maker cannot load any aliases, not just the one with the error. Always validate your JSON after editing. Use an online validator like JSONLint or a code editor with JSON highlighting.

Quick JSON Validation Checklist

  • Open config/CommandMaker/aliases.json in a text editor with JSON syntax highlighting
  • Look for red underlines (most editors highlight errors)
  • Copy the file contents to JSONLint and validate
  • Check that all braces {} and brackets [] are properly matched
  • Verify there are no trailing commas after the last item in an object or array
  • Make sure all strings use double quotes, not single quotes

Step 2: Use /cmd reload

After editing any configuration file, you must reload Command Maker for changes to take effect. This is one of the most common reasons aliases don't work after editing.

/cmd reload

Check the Reload Output

After running /cmd reload, watch the chat or server console for output. Command Maker will print messages about how many aliases were loaded, or if there were errors. Look for messages like these:

  • "Loaded 12 aliases" -- Everything is fine
  • "Error loading aliases.json" -- JSON syntax error (go back to Step 1)
  • "Skipped invalid alias: alias_name" -- A specific alias has an invalid command target
  • "0 aliases loaded" -- The file is likely empty or completely malformed

Step 3: Check Permissions

If the alias loads correctly but doesn't work for a specific player, the issue is likely permissions. Test the alias while opped first, then test as a regular player.

Permission Debugging Questions

  • Are you opped on the server? (/op <player>)
  • Does permissions.json have a permission level set for you?
  • Does the alias have a minimum permission level in alias_permissions?
  • If using LuckPerms, do you have the correct cmmaker.* node assigned?

Quick Permission Test

To quickly test if permissions are the issue, temporarily set the alias to ALIAS_USER (the default) in alias_permissions:

{
  "permissions": {
    "YourName": "ADMIN"
  },
  "alias_permissions": {
    "problem_alias": "ALIAS_USER"
  }
}

If the alias works after this change, the permission level was set too high. Gradually raise the level until you find the correct one.

Permissions and /cmd reload

Remember that permission changes also need /cmd reload to take effect. If you edit permissions.json but forget to reload, the old permissions will still apply.

Step 4: Verify Variables Resolve Correctly

If your alias includes ${player}, ${x}, ${y}, ${z}, or custom variables, they might not be resolving as expected.

Debug Variable Values

Create a simple debug alias to check what variables contain:

// Add this to your aliases.json and reload
"debug_vars": "say Player: ${player}, Position: ${x}, ${y}, ${z}"

Run /debug_vars and check the output. If you see literal ${player} in the chat message instead of your username, variables are not being substituted. This usually means the alias is running in a context where the player is not available (for example, from a command block or function).

Check Custom Variables

If you use /setcmdvariable for custom variables, verify they are set correctly:

/setcmdvariable YourName my_var "test_value"

Then in an alias:

"test_var": "say Custom variable value: ${my_var}"

Variable Resolution Order

Command Maker resolves variables in this order: (1) Built-in variables (${player}, ${x}, ${y}, ${z}), (2) Custom per-player variables (set with /setcmdvariable), (3) Syntax parameter variables (${syntaxName_paramName}). Later variables can reference earlier ones, but not vice versa.

Step 5: Test Commands Manually First

Before debugging an alias, test the raw command in Minecraft's chat to make sure it works on its own:

  1. Identify the raw command that your alias is supposed to execute. For example, if your alias is "heal": "effect give @s instant_health 1 1", the raw command is /effect give @s instant_health 1 1.
  2. Type the raw command directly in chat (with the slash). Does it work?
  3. If the raw command fails: The problem is the Minecraft command itself, not Command Maker. Check Minecraft's command syntax, spelling, and parameter order.
  4. If the raw command succeeds: The problem is in how Command Maker handles the alias. Move to the next debugging step.

Verify Tab Completion

Minecraft provides tab completion for commands. Type the beginning of a command and press Tab to see available options. This is a fast way to check if a command, target selector, or item name is valid. If tab completion doesn't show your alias, run /cmd reload first.

Step 6: Check Minecraft Logs

The Minecraft server log (logs/latest.log) contains detailed information about command execution errors. When an alias fails, there is often a stack trace or error message in the log that is not shown in-game.

Finding Relevant Log Entries

Look for these patterns in logs/latest.log:

  • [Command Maker] -- Command Maker's own log messages
  • [CHAT] -- Chat messages (includes command output)
  • Error executing command -- Minecraft command errors
  • java.lang.*Exception -- Java exceptions (these always indicate bugs)
  • Failed to parse JSON -- JSON parsing errors from Command Maker
  • Unknown command -- Command not found or alias not registered

Enabling Verbose Logging

For difficult bugs, you can enable debug logging in Minecraft's server.properties:

# In server.properties:
debug=true
enable-query=true

This produces more detailed logs but also more noise. Only enable debug mode while actively debugging, and disable it afterward to avoid filling your disk with log files.

Step 7: Common Error Messages and Their Fixes

Error Message Likely Cause Fix
Unknown command Alias not registered or not reloaded Run /cmd reload and verify the alias name has no typos
Incorrect argument for command Wrong syntax or parameter count Test the raw command in chat first, then check your alias target
You do not have permission Permission level too low Check permissions.json and the player's OP status
JSON parse error (in console) Invalid JSON in configuration file Validate JSON with an online validator
Failed to load aliases (in console) Corrupted or missing aliases.json Restore from backup or recreate the file
${player} not replaced Variable not resolving Check that the alias is running in a player context, not from console or command block
No such target selector Wrong selector syntax (e.g. @p vs @s) Verify selector syntax for your Minecraft version
Alias loops indefinitely Alias calls itself directly or indirectly Remove the self-reference from the alias or function chain
Function not found .mcfunction file missing or wrong name Check config/CommandMaker/Functions/ for the file with the exact name
Syntax pattern not matched Input doesn't match the defined pattern Verify the syntax.json pattern against your input

Step 8: The Divide and Conquer Method

For complex aliases with multiple chained commands or syntax parameters, use the "divide and conquer" approach to isolate the problem:

Example: A Complex Alias

Suppose this alias isn't working:

// Complex alias that does multiple things
"warp_teleport": "title ${player} actionbar {\"text\":\"Warping...\",\"color\":\"gold\"} && playsound minecraft:entity.enderman.teleport player ${player} ~ ~ ~ 1 1 && tp ${player} ${warp_coords} && say ${player} warped to ${warp_name}!"

Step-by-Step Isolation

  1. Split into individual commands: Create a separate alias for each part: 
    "test_1": "title ${player} actionbar {\"text\":\"Test\",\"color\":\"gold\"}"
"test_2": "playsound minecraft:entity.enderman.teleport player ${player} ~ ~ ~ 1 1"
"test_3": "tp ${player} 0 65 0"
"test_4": "say ${player} test!"
  2. Test each part independently: Run /test_1, /test_2, etc. Each one either works or doesn't. This tells you exactly which command is failing.
  3. Identify the failing component: Suppose /test_3 fails. Now you know the teleport command is the problem.
  4. Simplify the failing component: "test_3_simple": "tp @s 0 65 0". If this works, the issue was the ${player} variable or ${warp_coords} variable.
  5. Fix and rebuild: Once each part works individually, combine them back into the full alias one piece at a time.

Command Chaining vs Separate Aliases

The && chaining operator runs commands sequentially. If the first command fails, subsequent commands may still run, which can mask errors. When debugging, it's better to separate chained commands into individual test aliases so you can see exactly which one fails. Once everything works, you can recombine them.

Step 9: Check Version Compatibility

Minecraft commands change between versions. An alias that works in Minecraft 1.21 might fail in 1.22 due to:

  • Changed item names (e.g., minecraft:grass vs minecraft:grass_block)
  • Removed or renamed commands
  • Changed target selector syntax
  • Different NBT format for entities and blocks
  • Changed particle names
  • Modified sound effect names

Cross-Version Aliases

If you use Command Maker on multiple servers with different Minecraft versions, maintain separate aliases.json files for each version. What works on your 1.21 server may silently fail or behave differently on a 1.22 server due to command changes.

Debugging Workflow Summary

When an alias doesn't work, follow this workflow in order:

  1. Validate JSON -- Use a JSON validator to check your config file syntax
  2. Reload -- Run /cmd reload and check for error messages
  3. Check permissions -- Verify the player has sufficient permission level
  4. Test raw command -- Type the command directly in chat without the alias
  5. Check variables -- Create a simple debug alias to verify variable resolution
  6. Check logs -- Look at logs/latest.log for detailed error messages
  7. Divide and conquer -- Split complex aliases into individual parts to isolate the issue
  8. Check version -- Verify command syntax matches your Minecraft version

Getting Help

If you've gone through all debugging steps and the alias still doesn't work, check the FAQ for common questions, or review the Troubleshooting page for more specific scenarios. When asking for help, include: your Minecraft version, the full alias definition, the exact command you're typing, the error message (or a screenshot), and what debugging steps you've already tried.
