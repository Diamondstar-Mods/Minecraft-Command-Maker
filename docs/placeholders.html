Placeholder System

A Fabric-native placeholder engine using PlaceholderAPI-compatible %placeholder% syntax. Works in aliases, events, scoreboards, and cooldown messages.

New in v4.0 — Integrated into all command execution. No separate config file.

Syntax

%placeholder_name%

Placeholders are resolved after ${variable} substitution and before command execution.

Built-in Placeholders

PlaceholderResolves To
%player%Player name
%player_uuid%Player UUID
%player_health%Current health (e.g., 18.5)
%player_max_health%Maximum health (e.g., 20.0)
%player_xp%Total XP points
%player_xp_level%XP level
%player_food%Food level (0-20)
%player_world%Dimension ID (e.g., minecraft:overworld)
%player_gamemode%Game mode name
%player_ping%Network latency in ms
%server_online%Players currently online
%server_max%Maximum player slots
%server_tps%Server TPS (20.0 max)
%var_<name>%Value of custom variable <name>
%cooldown_<alias>%Seconds remaining on cooldown for <alias>

Usage Examples

// In an alias target
"status": "say %player% has %player_health% HP, level %player_xp_level%, in %player_world%"

// In a scoreboard line
"&7Health: &a%player_health%/%player_max_health%"

// In an event command
"title %player% title {\"text\":\"Welcome!\",\"color\":\"gold\"}"

Where Placeholders Work

  • Alias command targets
  • Event trigger commands
  • Scoreboard lines
  • Cooldown messages

Cross-Platform Compatibility

The placeholder system uses the same %name% format as PlaceholderAPI (PAPI). On the future Paper/Bukkit module, this system will bridge directly to real PAPI, allowing you to use any plugin's placeholders. The built-in placeholders use the same names across all platforms for seamless module sharing.

Custom Placeholders (Developer API)

Java developers can register custom placeholder resolvers at runtime:

PlaceholderManager.registerCustomPlaceholder("myplugin_balance", ctx -> {
    return String.valueOf(getBalance(ctx.player));
});
