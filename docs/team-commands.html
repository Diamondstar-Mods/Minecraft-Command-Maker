Team Commands

Leverage Minecraft's team system with Command Maker to create organized group mechanics, team-based chat, minigame support, and cooperative gameplay features.

Understanding Minecraft Teams

Minecraft's /team command allows you to group players into named teams with shared properties like friendly fire, collision rules, name tag visibility, and prefix/suffix formatting. When combined with Command Maker aliases, teams become a powerful organizational tool.

Command Description Example
/team add <name> Create a new team /team add red
/team join <team> <player> Add player to team /team join red Steve
/team leave <player> Remove player from team /team leave Steve
/team modify <team> <option> <value> Change team settings /team modify red color red
/team list [team] List teams or team members /team list red

Setting Up Teams

Creating Teams for a Minigame

# Create teams
/team add red
/team modify red color red
/team modify red prefix "[Red] "
/team modify red displayName "Red Team"
/team modify red friendlyfire false
/team modify red collisionRule pushOwnTeam

/team add blue
/team modify blue color blue
/team modify blue prefix "[Blue] "
/team modify blue displayName "Blue Team"
/team modify blue friendlyfire false
/team modify blue collisionRule pushOwnTeam

/team add spectator
/team modify spectator color gray
/team modify spectator prefix "[Spectator] "
/team modify spectator collisionRule never

Automated Team Setup Alias

/cmd add setup_teams team add red && team modify red color red && team modify red prefix "[Red] " && team modify red friendlyfire false && team add blue && team modify blue color blue && team modify blue prefix "[Blue] " && team modify blue friendlyfire false && say Teams created!

Pro Tip

Create a single /setup_teams alias that runs all the team creation commands. Use this whenever you reset your minigame or server. This avoids manual re-creation of teams after resets.

Team Chat Triggers

Team-Only Chat Alias

Create a team chat system where messages are only visible to team members:

/cmd add tc tell @a[team=red] [RED] ${player}: ${message}
/cmd add bc tell @a[team=blue] [BLUE] ${player}: ${message}

# With syntax support for the message parameter
# In syntax.json:
{
  "tc": {
    "pattern": "/tc <message>",
    "description": "Send message to red team"
  },
  "bc": {
    "pattern": "/bc <message>",
    "description": "Send message to blue team"
  }
}

This approach has a limitation -- each team needs its own alias. A more dynamic approach:

Dynamic Team Chat with Syntax

# In syntax.json:
{
  "teamchat": {
    "pattern": "/teamchat <team> <message>",
    "description": "Send message to your team"
  }
}

# In aliases.json:
{
  "teamchat": "tell @a[team=${teamchat_team}] [${teamchat_team}] ${player}: ${teamchat_message}"
}

# Usage:
# /teamchat red Hello teammates!
# /teamchat blue Attack the objective!

Self-Detecting Team Chat

For an even better experience, use the /teammsg command (Minecraft's built-in team chat) wrapped in an alias:

/cmd add t tell @a[team=red] ${player}: ${message}
# Or use: /cmd add t teammsg ${message}

Note

Minecraft's built-in /teammsg command already sends messages to the sender's team. However, Command Maker aliases let you customize the format, add prefixes, or trigger additional effects when team chat is used.

Team-Specific Permissions

Restricting Aliases by Team

Use the execute if entity command with team selectors to restrict alias usage to specific teams:

/cmd add blowup execute if entity @s[team=red] run say Red team used a special ability!
/cmd add blowup execute if entity @s[team=blue] run say You are not on the red team!

# Or with a permission check:
/cmd add heal execute if entity @s[team=red] run effect give @s instant_health 1
/cmd add heal execute if entity @s[team=blue] run effect give @s instant_health 1
/cmd add heal execute if entity @s[team=spectator] run say Spectators cannot use this!

Using Command Maker's Permission System with Teams

Combine Command Maker's permission levels with team membership for granular control:

# In permissions.json:
{
  "teams": {
    "red_leader": 4,
    "red_member": 2,
    "blue_leader": 4,
    "blue_member": 2,
    "spectator": 1
  },
  "aliases": {
    "red_ability": 2,
    "blue_ability": 2,
    "team_setup": 4
  }
}

# Alias with permission + team check:
/cmd add red_ability execute if entity @s[team=red] run say Red power activated!

Scoreboards with Teams

Team Scoreboards

Track team scores for minigames and competitions:

# Create a scoreboard for team kills
/scoreboard objectives add team_kills dummy "Team Kills"

# Alias to add a kill point to the team
/cmd add team_kill scoreboard players add red team_kills 1 && say Red team scores!

# Check team scores
/cmd add scores say === Team Scores === && scoreboard objectives setdisplay sidebar team_kills

# Reset scores
/cmd add reset_scores scoreboard players reset * team_kills && say Scores reset!

Team Score Display

/cmd add show_scores tellraw @a [
  {"text":"=== Team Scores ===\n","color":"gold","bold":true},
  {"text":"Red: ","color":"red"},
  {"text":"0","color":"white","score":{"name":"red","objective":"team_kills"}},
  {"text":"\nBlue: ","color":"blue"},
  {"text":"0","color":"white","score":{"name":"blue","objective":"team_kills"}}
]

Individual Contribution with Team Score

# Track individual kills and team kills simultaneously
/scoreboard objectives add kills dummy "Kills"
/scoreboard objectives add team_kills dummy "Team Kills"

# When a player scores a kill:
/cmd add score_kill scoreboard players add ${player} kills 1 && scoreboard players add ${team} team_kills 1

# But we need to determine the team. Use a syntax approach:
# In syntax.json:
{
  "score_kill": {
    "pattern": "/score_kill <team>",
    "description": "Add a kill to a team"
  }
}

# In aliases.json:
{
  "score_kill": "scoreboard players add ${score_kill_team} team_kills 1 && say Point for ${score_kill_team}!"
}

Example: Capture the Flag Minigame

Here is a complete team-based Capture the Flag system using Command Maker aliases:

Setup Phase

# Create teams (run once)
/cmd add ctf_setup
  team add red &&
  team modify red color red &&
  team modify red prefix "[Red] " &&
  team modify red friendlyfire false &&
  team add blue &&
  team modify blue color blue &&
  team modify blue prefix "[Blue] " &&
  team modify blue friendlyfire false &&
  scoreboard objectives add ctf_flag dummy "Has Flag" &&
  scoreboard objectives add ctf_score dummy "CTF Score" &&
  say Capture the Flag teams created!

# Join a team
/cmd add join_red team join red ${player} && say ${player} joined Red team!
/cmd add join_blue team join blue ${player} && say ${player} joined Blue team!

Gameplay Phase

# Pick up the flag
/cmd add grab_flag execute if entity @s[team=red] run scoreboard players set @s ctf_flag 1 && say Red player ${player} has the flag!
/cmd add grab_flag execute if entity @s[team=blue] run scoreboard players set @s ctf_flag 1 && say Blue player ${player} has the flag!

# Score a point (capture at own base)
/cmd add capture execute if entity @s[team=red,scores={ctf_flag=1}] run
  scoreboard players add red ctf_score 1 &&
  scoreboard players set @s ctf_flag 0 &&
  say Red team scores! Point for Red! &&
  playsound entity.experience_orb.pickup master @a

/cmd add capture execute if entity @s[team=blue,scores={ctf_flag=1}] run
  scoreboard players add blue ctf_score 1 &&
  scoreboard players set @s ctf_flag 0 &&
  say Blue team scores! Point for Blue! &&
  playsound entity.experience_orb.pickup master @a

# Show score
/cmd add ctf_score tellraw @a [
  {"text":"=== CTF SCORE ===\n","color":"gold","bold":true},
  {"text":"Red: ","color":"red"},
  {"text":"0","color":"white","score":{"name":"red","objective":"ctf_score"}},
  {"text":"    Blue: ","color":"blue"},
  {"text":"0","color":"white","score":{"name":"blue","objective":"ctf_score"}}
]

Cleanup Phase

# Reset the game
/cmd add ctf_reset
  scoreboard players reset * ctf_flag &&
  scoreboard players reset * ctf_score &&
  team leave @a[team=red] &&
  team leave @a[team=blue] &&
  say CTF game reset! Players can join new teams.

Example: Team-Based PvP Arena

# Team PvP setup
/cmd add pvp_setup
  team add fighters &&
  team modify fighters color gold &&
  team modify fighters prefix "[Fighter] " &&
  team modify fighters friendlyfire true &&
  scoreboard objectives add kills dummy "Kills" &&
  say PvP arena ready!

# Join the arena
/cmd add join_pvp team join fighters ${player} && tp ${player} 0 50 0 && say ${player} joined the PvP arena!

# Track kills
/cmd add pvp_kill scoreboard players add ${player} kills 1 && say ${player} got a kill! (Total: ${player_kills})

# Leaderboard
/cmd add pvp_top scoreboard objectives setdisplay sidebar kills && scoreboard players list

# Leave the arena
/cmd add leave_pvp team leave ${player} && tp ${player} 0 65 0 && say ${player} left the PvP arena!

Warning

When friendlyfire is set to true on a team, players on the same team can hurt each other. Only enable this for deliberate PvP arenas, never for cooperative games.

Advanced: Team Events and Triggers

Automatic Team Assignment on Join

Use Command Maker with a tick function to auto-assign players to the team with fewer members:

# Check every 20 seconds (400 ticks) to balance teams
/cmd add balance_teams
  execute if entity @a[team=red] if entity @a[team=blue] unless entity @a[team=red,scores={}] run
    team join red @p[team=!red,team=!blue,limit=1] &&
    say Auto-balanced: @p joined Red team!

# Run this from a repeating command block or scheduled function
/schedule function commandmaker:balance_teams 20s

Team Elimination Detection

# When all members of a team are eliminated
/cmd add check_elimination
  execute unless entity @a[team=red] run say Red team has been eliminated! Blue team wins! &&
  execute unless entity @a[team=blue] run say Blue team has been eliminated! Red team wins!

Best Practices for Team Commands

  • Always set friendlyfire appropriately for your game mode
  • Use prefixes to make team membership visible in chat
  • Set collisionRule to prevent team griefing
  • Create a help alias explaining available team commands
  • Team permissions are not built into Command Maker -- use execute if entity @s[team=...] for team-based restrictions
  • Reset teams between games to prevent stale data
  • Test with multiple players to verify team mechanics work correctly
  • Document your team system for other server administrators

Summary

Teams + Command Maker = powerful multiplayer mechanics. Use teams for minigames, organized chat, team-specific abilities, and automated score tracking. The combination of Minecraft's built-in team system and Command Maker's alias flexibility enables complex game systems without any plugins.
