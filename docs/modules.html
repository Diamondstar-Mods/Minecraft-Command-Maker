Command Maker Modules (.cmk)

Package your entire Command Maker setup — aliases, functions, events, scoreboards, cooldowns, syntaxes, and permissions — into a single .cmk file for sharing, backup, or distribution.

New in v4.0 — Packages directory: config/CommandMaker/packages/

What is a .cmk Module?

A .cmk file is a standard ZIP archive containing all your Command Maker configuration and function files. Think of it like a "modpack" for Command Maker — one file that contains everything someone needs to replicate your setup.

Module Structure

my_module.cmk/              ← ZIP archive (rename .zip to .cmk to inspect)
├── module.json             ← Metadata (required)
├── aliases.json            ← Alias definitions
├── syntax.json             ← Syntax patterns
├── events.json             ← Event triggers
├── scoreboards.json        ← Custom scoreboards
├── cooldowns.json          ← Cooldown configs
├── variables.json          ← Preset variables
├── permissions.json        ← Permission grants (optional)
└── functions/
    ├── welcome.mcfunction
    ├── starter_kit.mcfunction
    └── cleanup.mcfunction

module.json Format

{
  "name": "WelcomeKit",
  "version": "1.0.0",
  "author": "YourName",
  "description": "Welcome system with join messages, starter kit, and server info scoreboard.",
  "cmVersion": "4.0.0"
}
FieldRequiredDescription
nameYesModule name (shown in listings)
versionYesSemantic version (e.g., 1.0)
authorNoCreator name
descriptionNoWhat the module does
cmVersionNoMinimum Command Maker version required

Quick Commands (Recommended)

CommandDescription
/cmd package <name>Package everything (configs + functions) into config/CommandMaker/packages/<name>.cmk
/cmd import <name>Import a .cmk file from the packages folder (safe merge)
/cmd import <name> --overwriteImport with overwrite (replaces conflicts)

Advanced Module Commands

CommandDescription
/cmd module export <name>Export config only (no functions)
/cmd module exportall <name>Export including all .mcfunction files
/cmd module import <name>Import from packages folder (safe merge)
/cmd module listList available .cmk files
/cmd module info <name>Show module metadata without importing

Import Behavior

Safe Merge (default)

  1. Aliases that don't exist yet are added.
  2. Syntaxes, events, scoreboards, and cooldowns are merged — new entries added, existing ones preserved.
  3. Functions are extracted to the Functions/ folder.
  4. Conflicts are reported — nothing is silently overwritten.

Overwrite Mode (--overwrite)

  1. Existing aliases, syntaxes, events, scoreboards, and cooldowns with the same name are replaced.
  2. Use with caution — this can modify existing configurations.

Export Behavior

The export command packages your current in-memory config into a .cmk file:

  • All aliases from aliases.json
  • All syntaxes from syntax.json
  • Event config from events.json
  • Scoreboard config from scoreboards.json
  • Cooldown config from cooldowns.json
  • Functions (only with exportall — regular export skips them to keep files small)

The package is saved to config/CommandMaker/packages/<name>.cmk.

Sharing Packages

  1. Create your aliases, syntaxes, events, scoreboards, cooldowns, and functions.
  2. Run /cmd package MySetup.
  3. Find MySetup.cmk in config/CommandMaker/packages/.
  4. Share the file — it's just a ZIP. Rename to .zip to inspect, or use as-is.
  5. Recipient drops it in their packages/ folder and runs /cmd import MySetup.
Future: Web GUI Editor — A browser-based drag-and-drop GUI editor is planned that will output .cmk files. Design GUIs visually, export as a module, and import into the server. Stay tuned!
Note: Modules do not include player-specific data (custom variables set via /cmd setvar). They package configuration, not runtime state.
