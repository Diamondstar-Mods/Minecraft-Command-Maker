1. Built-in Cooldown System

Add per‑player and global cooldowns to any alias. No more players spamming commands — set cooldown timers with custom messages right in cooldowns.json.

How it Works

  • Per-player cooldowns: Each player has their own timer. Cooldown only affects the player who used the command.
  • Global cooldowns: Server-wide cooldown. Once any player uses the alias, nobody can use it until the cooldown expires.
  • Custom messages: Configure your own cooldown message with {remaining} to show seconds left.

Configuration

// config/CommandMaker/cooldowns.json
{
  "cooldowns": {
    "home": {
      "type": "player",
      "seconds": 30,
      "message": "&cWait {remaining}s before using /home again!"
    },
    "heal": {
      "type": "global",
      "seconds": 60,
      "message": "&cServer cooldown: {remaining}s remaining"
    }
  }
}

Commands

  • /cmd cooldown set <alias> player|global <seconds> [message]
  • /cmd cooldown clear <alias>
  • /cmd cooldown list

Variables

Check cooldown status in aliases with ${cooldown_alias_remaining} — resolves to seconds left, or 0 if ready.

2. Condition Blocks (If / Else)

Add logic to your aliases. Check player XP, health, permissions, inventory items, dimensions, and more — then run different commands based on the result.

Syntax

if:<condition>(<args>) <true_command> else <false_command>

Supported Conditions

ConditionArgsExample
xpXP levelsif:xp(30) give @s diamond
healthHealth %if:health(50) say I need healing!
permPermission nodeif:perm(cmdmaker.admin) say Admin here
hasitemItem IDif:hasitem(minecraft:diamond) say Rich!
varname valueif:var(team blue) tp @s blue_spawn
cooldownAlias nameif:cooldown(home) say Still waiting else home
playerPlayer nameif:player(Steve) say Hello Steve!
dimensionDimension ID or shorthandif:dimension(nether) say In nether
op(none)if:op() say You are op

3. Event Triggers

Run commands automatically when things happen in-game. Configure event handlers that fire on player join, death, chat, block break, first join, and more — with optional cooldowns and block filters.

Supported Events

  • player_join — When a player joins the server
  • player_leave — When a player leaves
  • player_death — When a player dies (context: ${death_cause}, ${killer})
  • player_respawn — When a player respawns
  • player_first_join — When a player joins for the very first time
  • player_chat — When a player sends a chat message (context: ${message})
  • player_kill — When a player kills another player
  • block_break — When a player breaks a block (context: ${block}, ${block_x}, etc.)

Configuration

// config/CommandMaker/events.json
{
  "events": {
    "player_join": {
      "commands": ["say Welcome ${player}!", "give ${player} minecraft:bread 3"]
    },
    "player_death": {
      "commands": ["say ${player} died!"],
      "cooldown": 0
    },
    "player_first_join": {
      "commands": ["say Everyone welcome ${player} — first time on the server!"]
    }
  }
}

Commands

  • /cmd event list — Show configured events
  • /cmd event reload — Reload events config

4. Custom Scoreboards

Define persistent, auto-updating scoreboards with dynamic lines. Use placeholders like ${player_count} and ${tps} that update automatically on a configurable interval.

Configuration

// config/CommandMaker/scoreboards.json
{
  "scoreboards": {
    "server_info": {
      "displayName": "&6&lServer Info",
      "slot": "sidebar",
      "updateInterval": 20,
      "lines": [
        "&6&lMy Server",
        "&f",
        "&7Players: &a${player_count}/${server_max}",
        "&7TPS: &a${tps}",
        "&f",
        "&7Powered by",
        "&eCommand Maker v4"
      ]
    }
  }
}

Features

  • Display slots: sidebar, list (tab list), or belowName
  • Dynamic updates: Set updateInterval in ticks (20 = 1 second). Use 0 for static scoreboards.
  • Placeholders: ${player_count}, ${server_max}, ${tps}, and any custom variable
  • Color codes: Full & color code support
  • Multiple scoreboards: Define as many as you want — each can be in a different slot

Commands

  • /cmd scoreboard list — Show custom scoreboards
  • /cmd scoreboard reload — Reload scoreboards config

5. Placeholder System

A Fabric-native placeholder system using %placeholder% syntax — compatible with PlaceholderAPI format for cross-platform support. Placeholders work everywhere: aliases, events, scoreboards, cooldown messages, and more.

Built-in Placeholders

PlaceholderResolves To
%player%Player name
%player_uuid%Player UUID
%player_health%Current health (formatted)
%player_max_health%Maximum health
%player_xp%XP points
%player_xp_level%XP level
%player_food%Food level
%player_world%Current world/dimension
%player_gamemode%Game mode
%player_ping%Ping in ms
%server_online%Online player count
%server_max%Max player slots
%server_tps%Server TPS
%var_<name>%Custom variable value
%cooldown_<alias>%Cooldown remaining for alias

On the upcoming Paper/Bukkit module, the placeholder system will bridge directly to PlaceholderAPI, allowing you to use any PAPI placeholder from other plugins. The same placeholder names work across all platforms.

6. Command Maker Modules (.cmk)

Package your aliases, functions, syntaxes, events, scoreboards, and cooldowns into a single .cmk file — then share, import, and export with one command. Think of it like a "modpack" for Command Maker content.

.cmk File Format

A .cmk file is a ZIP archive containing:

my_module.cmk/
├── module.json        ← name, version, author, description
├── aliases.json       ← alias definitions
├── syntax.json        ← syntax patterns
├── events.json        ← event triggers
├── scoreboards.json   ← custom scoreboards
├── cooldowns.json     ← cooldown configs
├── variables.json     ← preset variables
├── functions/
│   ├── myfunc.mcfunction
│   └── ...
└── permissions.json   ← (optional) permission grants

module.json

{
  "name": "WelcomeKit",
  "version": "1.0",
  "author": "YourName",
  "description": "A welcome system with join messages, starter kit, and server info scoreboard.",
  "cmVersion": "4.0.0"
}

Commands

  • /cmd module export <name> — Package current config into a .cmk file
  • /cmd module exportall <name> — Export including all .mcfunction files
  • /cmd module import <name> [--overwrite] — Import a .cmk module
  • /cmd module list — List available .cmk files
  • /cmd module info <name> — Show module metadata without importing

Import Behavior

  • Smart merging: New aliases, syntaxes, and configs are merged into existing ones
  • Conflict detection: If an alias already exists, it's skipped and reported
  • Overwrite mode: Use --overwrite to replace existing entries
  • Function extraction: .mcfunction files are extracted to the Functions folder

7. Web-Based GUI Editor (Future)

This feature is planned for a future update and will complement the module system.

A browser-based drag-and-drop editor for designing in-game GUIs. The website will let you visually place items in slots, set click actions, choose icons, and export the result as a .cmk module file that the server imports.

  • Fully server-side: The editor runs in your browser — no client mod needed
  • Export as .cmk: Generated GUIs are packaged as importable modules
  • Visual design: Drag items, set click handlers, preview layouts
