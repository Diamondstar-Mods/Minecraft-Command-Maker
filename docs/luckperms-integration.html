LuckPerms Integration

Command Maker supports LuckPerms as an optional permission backend. When LuckPerms is installed on your server, Command Maker automatically detects it and reads permission data from LuckPerms instead of (or in addition to) the built-in permissions.json system.

LuckPerms Is Optional

LuckPerms is not required to use Command Maker. The built-in permissions.json system works perfectly for most servers. LuckPerms integration is useful when you already use LuckPerms for other plugins and want to manage all permissions from a single place. In the mod's build, LuckPerms is marked as compileOnly, meaning it is not bundled with the mod and must be installed separately.

Installation Requirements

Before you begin, make sure both mods are installed and running:

  1. Install LuckPerms: Download the LuckPerms Fabric jar for your Minecraft version from the LuckPerms website or Modrinth. Place it in your server's mods/ folder.
  2. Verify both mods are loaded: Run /luckperms to check LuckPerms is working, and /cmd to check Command Maker is working.
  3. No additional configuration needed: Command Maker detects LuckPerms automatically. There is no setting to enable or disable the integration.

Server Restart Required

You must restart your server after adding LuckPerms to the mods folder. A simple /reload may not fully initialize the LuckPerms integration with Command Maker.

Permission Nodes

Command Maker registers the following LuckPerms permission nodes under the cmmaker root:

Permission Node Corresponding Level Description
cmmaker.admin ADMIN (4) Full access to all Command Maker features
cmmaker.moderator MODERATOR (3) Add/delete aliases, manage permissions, reload config
cmmaker.command COMMAND_USER (2) Use /cmd to view info, run all aliases and functions
cmmaker.alias ALIAS_USER (1) Run aliases and functions
cmmaker.* ADMIN (4) Wildcard granting all Command Maker permissions

How Nodes Map to Permission Levels

When Command Maker checks a player's permission, it looks for the highest-level node the player has. For example, if a player has cmmaker.alias, they get ALIAS_USER. If they have cmmaker.command, they get COMMAND_USER (which includes all ALIAS_USER abilities). The system checks from highest to lowest and uses the first match.

The wildcard cmmaker.* grants the equivalent of ADMIN level, giving full access to everything.

Setting Up Groups

The recommended approach is to create LuckPerms groups that mirror your server roles and assign the relevant cmmaker.* nodes to each group:

Step 1: Create Groups

/lp creategroup admin
/lp creategroup moderator
/lp creategroup helper
/lp creategroup vip
/lp creategroup default

Step 2: Assign Permission Nodes

# Admin group - full access
/lp group admin permission set cmmaker.* true

# Moderator group - moderate and manage
/lp group moderator permission set cmmaker.moderator true

# Helper group - use commands and aliases
/lp group helper permission set cmmaker.command true

# VIP group - use aliases and functions
/lp group vip permission set cmmaker.alias true

# Default group - use aliases and functions (same as VIP)
/lp group default permission set cmmaker.alias true

Step 3: Set Up Inheritance

Use inheritance so higher-ranked groups automatically include lower-ranked permissions. This mirrors the Command Maker permission level hierarchy:

# Helper inherits from default
/lp group helper parent add default

# Moderator inherits from helper
/lp group moderator parent add helper

# Admin inherits from moderator
/lp group admin parent add moderator

Verifying Group Setup

Check your group configuration at any time with /lp group <group> info. This displays all permissions, parents, and members of the group, making it easy to spot misconfigurations.

Step 4: Assign Players to Groups

/lp user Steve parent set admin
/lp user Alex parent set moderator
/lp user HelperBob parent set helper
/lp user VIPPlayer parent set vip

Per-Alias Permissions via LuckPerms

You can also control access to individual aliases through LuckPerms. When a player tries to use an alias, Command Maker checks the alias_permissions section of permissions.json against the player's LuckPerms-derived permission level. This means you define which aliases require which level in permissions.json, and LuckPerms determines which level each player gets.

Example permissions.json that relies solely on LuckPerms for player levels:

{
  "permissions": {},
  "alias_permissions": {
    "ban": "MODERATOR",
    "kick": "MODERATOR",
    "stop": "ADMIN",
    "broadcast": "COMMAND_USER",
    "spawn": "ALIAS_USER",
    "home": "ALIAS_USER"
  }
}

With this setup, the permissions section is empty because player levels are managed through LuckPerms groups and nodes. The alias_permissions section still controls which aliases require which level.

Advanced: Contextual Permissions

LuckPerms supports contextual permissions that apply only in certain worlds, at certain times, or under other conditions. You can use this to restrict Command Maker permissions by world:

# cmmaker.alias only in the survival world
/lp group default permission set cmmaker.alias true world=survival

# Full admin powers in the admin world
/lp group admin permission set cmmaker.* true world=admin

Context Limitations

Command Maker reads the player's global LuckPerms permission state, not world-specific overrides. Contextual permissions may not work as expected in all cases. Test thoroughly if you rely on world-specific permission contexts.

Prefix and Suffix Support

Command Maker does not directly use LuckPerms prefix/suffix data, but you can still use LuckPerms prefixes in your aliases by combining them with other chat formatting plugins. The ${player} variable always resolves to the player's username. For prefix-aware chat messages, consider using a separate chat formatting plugin alongside Command Maker.

If you want to include rank prefixes in your alias responses, you can use custom variables set per-player with /setcmdvariable:

# Set a player's prefix variable (run by an admin)
/setcmdvariable Steve prefix "[ADMIN] "

# Alias using the custom variable
"admin_say": "say ${prefix}${player}: ${message}"

Debugging LuckPerms Integration

If Command Maker is not respecting your LuckPerms configuration, follow these debugging steps:

Issue Check Solution
Permission nodes not working Verify nodes with /lp user <player> permission check cmmaker.alias Re-apply the permission node with /lp user <player> permission set cmmaker.alias true
Group inheritance not working Check /lp group <group> info for parent groups Re-apply parent groups and verify the chain: default < helper < moderator < admin
OP status overriding LuckPerms Check if player is opped with /lp user <player> info Deop the player with /deop <player> or grant cmmaker.* via LuckPerms
Permission changes not applied Run /lp sync to reload all LuckPerms data Also run /cmd reload to refresh Command Maker's state
"Unknown permission node" in LP Command Maker may not have registered its nodes yet Restart the server with both mods installed; the nodes register on startup

Complete Example Setup

Here is a complete example that configures a small server with three tiers:

# === STEP 1: Create groups ===
/lp creategroup admin
/lp creategroup staff
/lp creategroup member

# === STEP 2: Set permissions ===
/lp group member permission set cmmaker.alias true
/lp group staff permission set cmmaker.command true
/lp group staff parent add member
/lp group admin permission set cmmaker.* true
/lp group admin parent add staff

# === STEP 3: Assign players ===
/lp user Steve parent set admin
/lp user Alex parent set staff
/lp user GuestPlayer parent set member

# === STEP 4: Verify ===
/lp user Steve permission check cmmaker.*
/lp user Alex permission check cmmaker.command
/lp user GuestPlayer permission check cmmaker.alias

Then, in config/CommandMaker/permissions.json:

{
  "permissions": {},
  "alias_permissions": {
    "stop": "ADMIN",
    "ban": "MODERATOR",
    "kick": "MODERATOR",
    "broadcast": "COMMAND_USER",
    "spawn": "ALIAS_USER",
    "home": "ALIAS_USER"
  }
}

With this setup:

  • Steve (admin) can use all aliases including /stop
  • Alex (staff) can use /ban, /kick, /broadcast, and all player commands, but not /stop
  • GuestPlayer (member) can only use /spawn and /home
