Variable Reference

Variables are placeholders that Command Maker replaces with real values when an alias runs. This page is the complete reference for every variable type available.

How to Use Variables

Simply type ${variable_name} anywhere in your alias target. When the alias executes, the placeholder is replaced with the actual value. Variables work in /cmd add commands, aliases.json entries, and .mcfunction files.

Built-in Variables

These variables are always available and do not require any setup. They are populated automatically when a player executes a command.

Variable Description Example Value Use Case
${player} The username of the player who ran the command. Alex Personalized messages, targeting the command sender, logging who performed an action.
${x} The player's current X coordinate (east-west position). 123 Teleportation, marking locations, building reports, saving positions.
${y} The player's current Y coordinate (elevation). 65 Checking altitude, teleporting with height adjustment, cave detection.
${z} The player's current Z coordinate (north-south position). -450 Teleportation, marking locations, building reports.
${world} The name of the world or dimension the player is in. minecraft:overworld Dimension-aware commands, world-specific logic, logging player locations.
${dimension} An alias for ${world}. Returns the dimension identifier. minecraft:the_nether Same as ${world}, provided for readability and compatibility.

Built-in Variable Examples

/cmd add whereami say ${player}, you are at X:${x} Y:${y} Z:${z} in ${world}

Example output: Alex, you are at X:123 Y:65 Z:-450 in minecraft:overworld

/cmd add netherport tp ${player} ${x} 80 ${z} && say Teleported you above the nether ceiling!

This preserves the player's X and Z coordinates but sets Y to 80, effectively teleporting them above the nether roof.

Custom Variables

Custom variables are defined by server administrators using the /setcmdvariable command. They are stored in config/CommandMaker/variables.json and persist across server restarts. Use them for values that do not change often.

Managing Custom Variables

Action Command Example
Create or update /setcmdvariable <name> <value> /setcmdvariable server_name "My Server"
View all variables /setcmdvariable list /setcmdvariable list
Delete a variable Edit variables.json directly Remove the entry from the file and run /cmd reload

Common Custom Variable Examples

Variable Set Command Usage in Alias
${server_name} /setcmdvariable server_name "AdventureCraft" say Welcome to ${server_name}!
${spawn_coords} /setcmdvariable spawn_coords "0 100 0" tp ${player} ${spawn_coords}
${discord_url} /setcmdvariable discord_url "discord.gg/myserver" say Join us: ${discord_url}
${rules_url} /setcmdvariable rules_url "example.com/rules" say Read the rules: ${rules_url}
${max_players} /setcmdvariable max_players "20" say Max players: ${max_players}
${motd} /setcmdvariable motd "Have a great day!" say ${motd}
${welcome_message} /setcmdvariable welcome_message "Welcome to the server!" say ${welcome_message}, ${player}!

Full Custom Variable Example

/setcmdvariable server_name "SkyBlock Network"
/setcmdvariable spawn_island "0 70 0"
/setcmdvariable discord_url "discord.gg/skyblock"
/setcmdvariable motd "Build high, dream big!"

/cmd add spawn tp ${player} ${spawn_island} && say Welcome to ${server_name}!
/cmd add motd say ${motd}
/cmd add social say Discord: ${discord_url} | Server: ${server_name}

Custom Variable Rules

  • Variable names must not contain spaces. Use underscores: ${my_variable}.
  • Names can contain letters, numbers, and underscores.
  • Variable names are case-sensitive: ${ServerName} and ${server_name} are different.
  • Use lowercase for consistency and to avoid case-related bugs.
  • Values containing spaces must be wrapped in quotes: /setcmdvariable msg "Hello world".

Syntax Parameters (Pattern Variables)

When you define a custom syntax pattern, its parameters become available as variables. The variable name follows this format:

${patternName_paramName}

Where patternName is the key in syntax.json and paramName is the parameter name inside angle brackets.

Pattern Definition User Input Variables Created Variable Values
"tpa": { "pattern": "/tpa <player>" } /tpa Steve ${tpa_player} Steve
"ban": { "pattern": "/ban <player> <reason>" } /ban Steve griefing ${ban_player}, ${ban_reason} Steve, griefing
"shop": { "pattern": "/shop <item> <quantity>" } /shop diamond 64 ${shop_item}, ${shop_quantity} diamond, 64
"warp": { "pattern": "/warp <name>" } /warp spawn ${warp_name} spawn
"msg": { "pattern": "/msg <target> <message>" } /msg Steve See you later! ${msg_target}, ${msg_message} Steve, See you later!
"pay": { "pattern": "/pay <target> <amount>" } /pay Alex 500 ${pay_target}, ${pay_amount} Alex, 500

Syntax Variable in Aliases

{
  "tpa": {
    "pattern": "/tpa <player>",
    "description": "Request teleport to a player"
  }
}

// In aliases.json or /cmd add:
/cmd add tpa_request say ${player} wants to teleport to ${tpa_player}!

Typing /tpa Notch produces: Alex wants to teleport to Notch!

Greedy Parameters

The last parameter in a pattern captures everything typed after the previous parameter, including spaces. This means ${ban_reason} in the example above would capture griefing the spawn area as a complete string if the user types /ban Steve griefing the spawn area.

Variable Type Comparison

Feature Built-in Variables Custom Variables Syntax Parameters
Setup required None — always available Must be created with /setcmdvariable Must define pattern in syntax.json
Value source Player's current game state Admin-defined, stored in variables.json Player's typed input at runtime
Changes per player Yes — each player sees own values No — same value for everyone Depends on input — each execution may differ
Example ${player} → Alex ${server_name} → MyServer ${tpa_player} → Steve
Scope Global — works in any alias Global — works in any alias Only within aliases using that pattern

Combining Multiple Variable Types

You can mix all three variable types freely in a single alias. Here is an example that uses built-in, custom, and syntax variables together:

/setcmdvariable server_name "AdventureCraft"

{
  "tpa": {
    "pattern": "/tpa <player>",
    "description": "Request teleport to a player"
  }
}

/cmd add tpa say [${server_name}] ${player} wants to teleport to ${tpa_player} at their location!

When Alex runs /tpa Steve, the output is: [AdventureCraft] Alex wants to teleport to Steve at their location!

Variable Naming Rules (Summary)

  • Format: ${name} with curly braces required.
  • Case sensitivity: ${Player} and ${player} are different. Always use lowercase.
  • Allowed characters: Letters (a-z), numbers (0-9), and underscores (_).
  • No spaces: Use underscores instead: ${my_variable}.
  • Syntax parameter format: ${patternName_paramName} — pattern name, underscore, parameter name.
  • Custom variable names: Cannot conflict with built-in variable names.

Common Mistake

Writing $player instead of ${player} will not work. The curly braces are mandatory. Command Maker only recognizes ${variable} syntax, not $variable.

Troubleshooting Variables

Symptom Likely Cause Fix
${player} appears literally in output Variable is not being substituted Run /cmd reload. Check that the variable name is spelled correctly and uses curly braces.
Custom variable shows nothing Variable was never set or name is wrong Run /setcmdvariable to verify it exists. Check for case mismatch.
Syntax variable is empty Pattern does not match the input Verify the pattern in syntax.json. Check that variable name uses ${pattern_param} format.
Coordinates show as 0 Player is in a different dimension or just joined Move the player or wait for position data to load.
