Backup & Restore

Protect your Command Maker configuration with proper backup practices. This guide covers what to back up, how to automate backups, and how to restore from them.

Why Backups Matter

Your Command Maker configuration represents time spent building aliases, crafting syntax patterns, and fine-tuning permissions. Without backups, a corrupted JSON file, accidentally deleted alias, or server crash can erase hours of work. A proper backup strategy ensures you can recover quickly.

Important

Command Maker stores all configuration on the server side. If you are a player using a server, you cannot back up configurations -- only the server administrator can. If you run a single-player world, the configuration is in your .minecraft directory.

What to Back Up

Essential Files

The entire config/CommandMaker/ directory contains all your configuration data. These are the specific files you need:

File/Folder Description Backup Frequency
config/CommandMaker/aliases.json All custom aliases After every alias change
config/CommandMaker/syntax.json Custom syntax patterns After pattern changes
config/CommandMaker/permissions.json Permission configuration After permission changes
config/CommandMaker/variables.json Custom variables Periodically (changes less often)
config/CommandMaker/Functions/ Uploaded .mcfunction files After function changes

Optional Files

  • Server properties -- If your aliases reference server-specific settings
  • Datapack files -- If you use custom datapacks alongside Command Maker
  • Scoreboard data -- If your aliases depend on scoreboard values (back up via /scoreboard commands)

How to Back Up

Manual Backup

The simplest method -- copy the entire configuration folder:

# Stop the server first (recommended)
# Navigate to the server directory
cd /path/to/server

# Copy the configuration
cp -r config/CommandMaker backups/CommandMaker_2026-05-26

# Or on Windows:
# xcopy /E /I config\CommandMaker backups\CommandMaker_2026-05-26

Pro Tip

Always use date-stamped backup folders. This lets you track changes over time and revert to specific versions if needed. Format: CommandMaker_YYYY-MM-DD or CommandMaker_YYYY-MM-DD_HHMM for multiple backups in one day.

Automated Backup Scripts

Linux / macOS (Bash)

#!/bin/bash
# Save as: backup-commandmaker.sh

BACKUP_DIR="/path/to/backups/commandmaker"
SOURCE_DIR="/path/to/server/config/CommandMaker"
TIMESTAMP=$(date +%Y-%m-%d_%H%M)
FILENAME="CommandMaker_${TIMESTAMP}.tar.gz"

mkdir -p "$BACKUP_DIR"
tar -czf "${BACKUP_DIR}/${FILENAME}" -C "$(dirname "$SOURCE_DIR")" CommandMaker/

# Keep only the last 30 backups
ls -t "$BACKUP_DIR"/CommandMaker_*.tar.gz | tail -n +31 | xargs -r rm

echo "Backup saved: ${BACKUP_DIR}/${FILENAME}"

Windows (PowerShell)

# Save as: backup-commandmaker.ps1

$backupDir = "C:\backups\commandmaker"
$sourceDir = "C:\server\config\CommandMaker"
$timestamp = Get-Date -Format "yyyy-MM-dd_HHmm"
$filename = "CommandMaker_$timestamp.zip"

New-Item -ItemType Directory -Force -Path $backupDir
Compress-Archive -Path "$sourceDir\*" -DestinationPath "$backupDir\$filename" -Force

# Keep only the last 30 backups
Get-ChildItem "$backupDir\CommandMaker_*.zip" |
    Sort-Object Name -Descending |
    Select-Object -Skip 30 |
    ForEach-Object { Remove-Item $_.FullName }

Write-Output "Backup saved: $backupDir\$filename"

Scheduling Automated Backups

Linux (cron): Run crontab -e and add:

# Daily backup at 3:00 AM
0 3 * * * /path/to/backup-commandmaker.sh

Windows (Task Scheduler):

  1. Open Task Scheduler
  2. Create Basic Task
  3. Trigger: Daily at 3:00 AM
  4. Action: Start a program
  5. Program: powershell.exe
  6. Arguments: -File "C:\scripts\backup-commandmaker.ps1"

Version Control for Configurations

Using Git

For advanced users, tracking configuration changes with Git provides the most flexibility:

# Initialize a repository in your backup location
cd /path/to/backups/commandmaker-git
git init

# Copy the configuration
cp -r /path/to/server/config/CommandMaker/* .

# Stage and commit
git add .
git commit -m "Backup: Command Maker config 2026-05-26"

# View changes over time
git log --oneline
git diff HEAD~1 -- aliases.json

.gitignore for Sensitive Data

If your repository is public or shared, exclude sensitive information:

# .gitignore for Command Maker backups
variables.json
*.tmp
*.log

Note

Custom variables may contain server IP addresses, Discord invite links, or other semi-sensitive data. Use discretion when sharing backups publicly.

Restoring from Backup

Standard Restore Procedure

  1. Stop the Minecraft server to prevent file conflicts
  2. Navigate to the backup location
  3. Restore the files to config/CommandMaker/
  4. Start the server
  5. Verify the configuration by running /cmd reload
  6. Test critical aliases to confirm they work
# Linux restore from tar.gz
cd /path/to/server
tar -xzf /path/to/backups/commandmaker/CommandMaker_2026-05-26.tar.gz
# This extracts into config/CommandMaker/ automatically

# Windows restore from zip
# Extract the zip file directly into the server directory
# ensuring the folder structure is preserved

Partial Restore

If only one file is corrupted or lost, restore it individually:

# Restore only aliases.json
cp /path/to/backup/aliases.json /path/to/server/config/CommandMaker/aliases.json

# Restore only the Functions folder
cp -r /path/to/backup/Functions /path/to/server/config/CommandMaker/Functions

Disaster Recovery

Complete Server Loss

If the entire server is lost (hardware failure, corruption, accidental wipe):

  1. Install Minecraft server with the same version
  2. Install your mod loader (Fabric/Forge/NeoForge) and Fabric API if using Fabric
  3. Install Command Maker mod
  4. Copy your latest backup to config/CommandMaker/
  5. Start the server and run /cmd reload
  6. Verify all aliases work correctly

Corrupted JSON File

If a JSON file becomes corrupted (e.g., from an interrupted save):

  1. Stop the server immediately
  2. Locate the corrupted file -- the console log will show which file failed to parse
  3. Replace it with the backup version
  4. Start the server and verify
# Quick fix for corrupted aliases.json
cp /path/to/backup/aliases.json config/CommandMaker/aliases.json
/cmd reload  # After server start

Warning

If you don't have a backup of a corrupted JSON file, you will lose that configuration data. The mod will create a new empty file if the old one is unreadable, but it cannot recover your lost aliases.

Accidental Alias Deletion

If you delete an alias with /cmd remove and regret it:

  • Restore from backup -- copy the old aliases.json over the current one
  • Manually re-add -- if you remember the command, use /cmd add
  • Check Git history -- if using version control, check the last commit

Backup Strategy Recommendations

Server Type Recommended Strategy Retention
Personal / Small Manual backup before major changes Keep last 3-5 backups
Community Server Automated daily backup + manual before changes Keep last 30 daily backups
Large Network Automated hourly + daily + Git version control Keep 7 days hourly, 90 days daily
Development/Test Git version control with every change Keep full history

Backup Checklist

Before Making Changes

  • Back up the entire config/CommandMaker/ folder
  • Note the current date in the backup filename
  • Document what changes you plan to make
  • Test the backup is valid (can you open the files?)

After Making Changes

  • Test that all aliases work correctly
  • Create a dated backup of the working configuration
  • If using Git, commit the change with a descriptive message
  • Notify other admins of the backup location
