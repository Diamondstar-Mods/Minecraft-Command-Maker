Command Maker v4.0 Changelog

Six major new systems — cooldowns, condition blocks, event triggers, custom scoreboards, placeholder engine, and shareable .cmk modules.

Release Summary

Version 4.0 is the largest update since the Custom Syntax System. It adds six entirely new subsystems that transform Command Maker from an alias/syntax tool into a full server automation platform. Every feature uses JSON config files with auto-creation on first run. All features work together — conditions can check cooldowns, events can trigger aliases with placeholders, scoreboards update from server stats, and everything can be packaged into a single .cmk file for sharing.

1. Built-in Cooldown System

New file: config/CommandMaker/cooldowns.json | Manager: CooldownManager

  • Per-player cooldowns — each player has their own timer. Configure per alias.
  • Global cooldowns — server-wide lockout. Once any player runs the alias, everyone waits.
  • Custom cooldown messages — use {remaining} placeholder for countdown display with full & color support.
  • Cooldown variables — ${cooldown_alias_remaining} available in any alias command string.
  • Commands: /cmd cooldown set, /cmd cooldown clear, /cmd cooldown list
  • Integration: Cooldowns are checked automatically before any alias executes. No extra config needed in the alias itself.

2. Condition Blocks (If / Else)

Works in: Any alias target string | Manager: ConditionManager

  • Inline DSL syntax: if:type(args) true_command else false_command — place directly in alias targets.
  • 9 condition types: xp, health, perm, hasitem, var, cooldown, player, dimension, op
  • Else branches: Optional else clause for failed conditions.
  • Variable support: Conditions work after ${variable} substitution and before %placeholder% resolution.
  • Safe fallback: If a condition fails with no else, an empty string is returned (nothing executes) instead of a crash.
  • Integration: Conditions are evaluated in the alias execution pipeline — no separate command needed.
Full conditions documentation →

3. Event Triggers

New file: config/CommandMaker/events.json | Manager: EventManager

  • 8 event types: player_join, player_leave, player_death, player_respawn, player_first_join, player_chat, player_kill, block_break
  • Event variables: ${death_cause}, ${killer}, ${message}, ${block}, ${block_x}, etc. — provided automatically.
  • Block filters: Restrict block_break events to specific blocks.
  • Event cooldowns: Prevent event spam with per-event cooldown timers.
  • First-join detection: player_first_join fires only the very first time a player connects.
  • Fabric API native: Uses ServerPlayConnectionEvents, ServerLivingEntityEvents, PlayerBlockBreakEvents, ServerMessageEvents.
  • Commands: /cmd event list, /cmd event reload
Full events documentation →

4. Custom Scoreboards

New file: config/CommandMaker/scoreboards.json | Manager: ScoreboardManager

  • JSON-defined scoreboards: Full control over display name, slot position, update interval, and all lines.
  • Dynamic placeholders: ${player_count}, ${server_max}, ${tps} — auto-update at the configured interval.
  • Display slots: sidebar, list (tab menu), belowName.
  • Configurable update interval: Set in ticks (20 = 1 second). Use 0 for static scoreboards.
  • Enable/disable toggle: Each scoreboard has an enabled field. Defaults to false — no unwanted scoreboards.
  • Multiple scoreboards: Define as many as you need. Each can target a different display slot.
  • Color support: Full & color code support in display names and all lines.
  • Commands: /cmd scoreboard list, /cmd scoreboard reload
Full scoreboards documentation →

5. Placeholder System

Manager: PlaceholderManager

  • PAPI-compatible syntax: %placeholder% format — familiar to anyone who's used PlaceholderAPI.
  • 15 built-in placeholders: %player%, %player_uuid%, %player_health%, %player_xp%, %player_food%, %player_world%, %player_gamemode%, %player_ping%, %server_online%, %server_max%, %server_tps%, %var_name%, %cooldown_alias%
  • Custom placeholder API: Java developers can register custom placeholder resolvers at runtime.
  • Works everywhere: Resolved in alias commands, event command lists, scoreboard lines, cooldown messages, and GUI text.
  • Cross-platform: Same placeholder names work on Fabric, with Paper/Forge bridges planned for real PAPI integration.
Full placeholders documentation →

6. Command Maker Modules (.cmk)

Manager: ModuleManager | Directory: config/CommandMaker/Modules/

  • Shareable packages: Bundle aliases, syntaxes, functions, events, scoreboards, and cooldowns into one .cmk file.
  • ZIP format: Standard ZIP with module.json metadata + individual config files + functions/ directory.
  • One-command export: /cmd module export <name> packages everything up.
  • Smart import: Merges into existing config. Conflicts detected and reported. --overwrite flag forces replacement.
  • Metadata: Each module carries name, version, author, description, and target Command Maker version.
  • Function bundling: Functions are extracted to the Functions folder on import. Use /cmd module exportall to include them.
  • Module browser: /cmd module list shows available modules. /cmd module info shows metadata without importing.
Full modules documentation →

7. Updated Help & Commands

  • /cmd help now lists all 18+ subcommands including the 6 new feature groups.
  • All new commands follow the existing /cmd <feature> <action> pattern for consistency.
  • Config files auto-create with _comment fields explaining available options.

Breaking Changes

None. All existing aliases, syntaxes, permissions, and functions continue to work exactly as before. New features are opt-in via config files — nothing activates unless you configure it.

Upgrading from v3.x? Just replace the JAR. All new config files are created automatically on first run with safe defaults (all disabled). Your existing aliases, syntaxes, and permissions are untouched.
