Writing Functions

Functions are .mcfunction files that contain multiple commands executed in sequence. Command Maker automatically registers every function in its Functions folder as a usable command alias, making them a powerful way to create multi-step behavior.

If you just want an overview of the Functions system, read the Functions System page first.

File Format

A .mcfunction file is a plain text file with a simple format:

  • Each line is one Minecraft command.
  • Lines starting with # are comments and are ignored.
  • Blank lines are ignored and can be used for readability.
  • Commands execute top to bottom, one at a time.
  • Variables like ${player}, ${x}, ${y}, ${z} work in functions just like in aliases.

Basic Example

Save this as config/CommandMaker/Functions/heal_and_feed.mcfunction:

# Heals and feeds the player
effect give @s instant_health 1
effect give @s saturation 1
say You have been healed and fed!

Command Maker automatically creates the alias /heal_and_feed that runs all three commands in sequence.

Best Practices

Group Related Commands

A function should do one thing well. Do not combine unrelated commands into a single function. Instead, create separate functions for separate purposes:

# GOOD: Separate functions for separate purposes
# Functions/heal.mcfunction
effect give @s instant_health 1
say You were healed!

# Functions/feed.mcfunction
effect give @s saturation 1
say You were fed!

# Functions/ready.mcfunction  (calls both via alias chaining)
# (This can use && chaining instead)
# /cmd add ready run heal_and_feed && run ready_effects

Add Comments

Functions can grow long. Comments help you and other administrators understand what each section does:

# ============================================
# Welcome Package - gives new players a kit
# ============================================

# Give starter tools
give @s stone_sword 1
give @s stone_pickaxe 1
give @s stone_axe 1

# Give basic food
give @s bread 16
give @s cooked_beef 8

# Announce
say Welcome to the server! Check /help for available commands.
title @s title {"text":"Welcome!","color":"gold"}

Test Incrementally

When writing a complex function, build and test it one step at a time:

  1. Write the first command and test it alone.
  2. Add the second command and test the pair.
  3. Continue adding commands one by one, testing after each addition.
  4. If something breaks, you know exactly which command caused the problem.

Quick Testing

Run /cmd reload after editing a function file, then use /cmd function <name> to run it. This is faster than running the function directly when debugging.

Using Variables in Functions

Functions support the same variables as aliases. This lets you create functions that adapt to the player running them.

Built-in Variables in Functions

# Functions/whereami.mcfunction
say Player: ${player}
say Location: X=${x} Y=${y} Z=${z}
say Dimension: ${world}

When a player runs /whereami, they see their own name, coordinates, and dimension.

Custom Variables in Functions

# First, set up custom variables:
# /setcmdvariable spawn_point "0 70 0"
# /setcmdvariable spawn_region "spawn"

# Functions/spawn_teleport.mcfunction
tp ${player} ${spawn_point}
say ${player} teleported to the ${spawn_region}!
playsound minecraft:block.portal.travel master @s

Syntax Parameters in Functions

Functions themselves cannot accept direct parameters, but you can create an alias with syntax that calls a function:

{
  "warp": {
    "pattern": "/warp <name>",
    "description": "Teleport to a warp"
  }
}

/cmd add warp run warps_${warp_name}

Then create individual function files for each warp:

# Functions/warps_spawn.mcfunction
tp ${player} 0 70 0
say Teleported to spawn warp!
playsound minecraft:block.portal.travel master @s

# Functions/warps_arena.mcfunction
tp ${player} 1000 64 500
say Teleported to arena warp!
playsound minecraft:entity.wither.spawn master @s

Chaining with Execute

The /execute command is your most powerful tool inside functions. It lets you run commands conditionally or from a different context.

Conditional Execution

# Functions/admin_tools.mcfunction
# Check if the player is in creative mode (admin check)
execute if entity @s[gamemode=creative] run give @s command_block 1
execute if entity @s[gamemode=creative] run say Here is your command block, admin!
execute unless entity @s[gamemode=creative] run say You must be in creative mode to use this.

Location-Based Commands

# Functions/lightning_strike.mcfunction
# Strike lightning at the player's location
execute at @s run summon minecraft:lightning_bolt ~ ~ ~
playsound minecraft:entity.lightning_bolt.thunder master @s
say Lightning summoned!

Dimension-Aware Functions

# Functions/safe_spawn.mcfunction
# Teleport to spawn in the correct dimension
execute if entity @s[player] in minecraft:overworld run tp @s 0 70 0
execute if entity @s[player] in minecraft:the_nether run tp @s 0 70 0
execute if entity @s[player] in minecraft:the_end run tp @s 0 70 0
say Teleported to spawn!

Execute Chains

You can nest execute conditions. For example, execute if entity @s[gamemode=creative] at @s run setblock ~ ~-1 ~ minecraft:gold_block places a gold block under the player only if they are in creative mode.

Common Patterns

Server Announcement Sequence

# Functions/restart_warning.mcfunction
# Stage 1: 30-second warning
say [SERVER] Server will restart in 30 seconds!
title @a title {"text":"Restart Warning","color":"red"}
title @a subtitle {"text":"30 seconds remaining","color":"gold"}
playsound minecraft:block.note_block.pling master @a 1 1

Player Welcome Package

# Functions/new_player_kit.mcfunction
# Starter kit for new players
give @s minecraft:stone_sword 1
give @s minecraft:stone_pickaxe 1
give @s minecraft:stone_axe 1
give @s minecraft:bread 16
give @s minecraft:cooked_beef 8
give @s minecraft:torch 16
give @s minecraft:oak_planks 32

# Give a helpful book (requires a written book item)
give @s minecraft:written_book{pages:['{"text":"Welcome to the server! Use /help to see all commands."}'],title:"Server Guide",author:"Server"} 1

# Announce
say Welcome package delivered, ${player}!
title @s title {"text":"Welcome, ${player}!","color":"green"}

Event Zone Setup

# Functions/setup_arena.mcfunction
# Build a simple PvP arena
fill 0 4 0 10 4 10 minecraft:stone
fill 0 5 0 10 5 10 minecraft:air
setblock 5 5 5 minecraft:beacon
say Arena setup complete!

Night Skip (Without Sleeping)

# Functions/night_skip.mcfunction
# Fast-forward to day
time set day
weather clear
say [SERVER] Night has been skipped!
playsound minecraft:entity.experience_orb.pickup master @a

Combo: Heal, Buff, and Teleport to Spawn

# Functions/ready.mcfunction
# Full ready-up sequence

# Step 1: Heal and feed
effect give @s instant_health 1
effect give @s saturation 1

# Step 2: Clear negative effects
effect clear @s minecraft:slowness
effect clear @s minecraft:weakness
effect clear @s minecraft:poison

# Step 3: Apply buffs
effect give @s speed 300 1
effect give @s resistance 300 1

# Step 4: Teleport to spawn
tp ${player} ${spawn_coords}

# Step 5: Confirm
title @s title {"text":"Ready!","color":"green"}
playsound minecraft:entity.player.levelup master @s

Annotated Example: Parkour Checkpoint System

This complete example shows a parkour checkpoint function with detailed comments explaining each section:

# ============================================
# Functions/parkour_checkpoint.mcfunction
# Saves the player's current position as a
# parkour checkpoint and teleports them back
# to the start if they fall.
# ============================================

# --- Step 1: Store current position ---
# Use scoreboard or a location marker
setblock ${x} ${y} ${z} minecraft:lapis_block
say Checkpoint saved at ${x}, ${y}, ${z}!

# --- Step 2: Visual feedback ---
# Particle burst at checkpoint location
particle minecraft:dust 0 0 1 1 ${x} ${y} ${z} 0.5 0.5 0.5 0.1 10
playsound minecraft:block.note_block.chime master @s 1 2

# --- Step 3: Clear old checkpoint (if any) ---
# (This would need specific coordinate knowledge)
# setblock ${old_x} ${old_y} ${old_z} minecraft:air

# --- Step 4: Give grace effect ---
effect give @s slow_falling 3 0 true
say You have 3 seconds of slow falling. Use it wisely!

Function File Organization Tips

Tip Explanation
Use a naming prefix Prefix related functions like warps_spawn, warps_arena, warps_minigame to group them logically.
Keep functions short If a function exceeds 20 lines, consider splitting it into smaller functions that call each other.
Use header comments Start each file with a comment block explaining what the function does.
Back up regularly Copy the entire Functions/ folder periodically. Functions can be complex and are hard to rewrite from memory.
Test in singleplayer first Before deploying a function to a live server, test it in singleplayer or a test server to avoid unexpected behavior.

Calling Functions from Functions

You cannot directly call another .mcfunction file from within a function in Command Maker's system. However, you can achieve similar behavior using /schedule function or by creating a meta-alias that chains multiple function calls:

# Instead of calling a function from within a function,
# create an alias that runs multiple functions:
/cmd add full_setup run setup_arena && run spawn_mobs && run give_kits

This runs three functions in sequence as if they were one larger function.

Command Limit

Minecraft has a command length limit. For very large functions with many commands, make sure your total command string does not exceed the limit. If you hit the limit, split the function into smaller parts.
